# MinIO debug stack

A standalone two-MinIO compose plus seed fixtures, used for manual S3 debugging
and as the source of the joinable fixtures the python integration suite loads
into its own (single-bucket) MinIO via `compose.test.yml`.

> The previous C++ semi-integration target (`test_s3_manager`) has been
> removed. `conn::s3::ConnectorManager` and `db::S3Manager` are exercised
> end-to-end by the python integration suite — `tests/test_{schema_}mysql_s3.py`,
> `tests/test_mysql_join_sql_s3_to_s3.py`, `tests/test_mysql_join_otb_local_s3.py`,
> `tests/test_mysql_join_otb_local_s3_file.py` (3-origin: s3 ⋈ file ⋈
> otterbrix-internal) — driven by `docker-run-tests.sh`. Run those to validate the
> s3 path.

## Start / stop

```bash
docker compose -f tests/minio/docker-compose.yml up -d --wait   # start
docker compose -f tests/minio/docker-compose.yml down            # stop (keep data)
docker compose -f tests/minio/docker-compose.yml down -v         # stop + wipe data
```

Each `*-init` container waits for its MinIO to be healthy, creates the bucket,
and uploads everything in [`fixtures/`](fixtures/) into it.

| Service | S3 API (host)           | In-network    | Console                 | Bucket          |
|---------|-------------------------|---------------|-------------------------|-----------------|
| minio1  | `http://localhost:9000` | `minio1:9000` | `http://localhost:9001` | `test-bucket-1` |
| minio2  | `http://localhost:9010` | `minio2:9000` | `http://localhost:9011` | `test-bucket-2` |

Both use credentials `minioadmin` / `minioadmin`, region `us-east-1`.

## Dev-container workflow

The dev container runs on the external network `otterstax_app_network_debug`,
so MinIO must join that network to be reachable from in-container code.
[`manual_run.sh`](manual_run.sh) wraps the start/join sequence:

```bash
# ON THE HOST (outside the dev container):
tests/minio/manual_run.sh start   # MinIO up + joins the dev-container network
tests/minio/manual_run.sh stop    # tear it down
```

After `start`, MinIO is reachable as `minio1:9000` / `minio2:9000` from the
dev container and `localhost:9000` / `localhost:9010` from the host. Override
the network with `DEVCON_NETWORK=...` if your dev container differs.

## Poking at a running MinIO

[`s3cmd.sh`](s3cmd.sh) wraps `minio/mc` in a throwaway container — no host
install beyond Docker (defaults target minio1 / `test-bucket-1`):

```bash
./s3cmd.sh ls                                    # list the bucket
./s3cmd.sh up   fixtures/people.parquet          # upload (key defaults to basename)
./s3cmd.sh down people.parquet /tmp/got.parquet  # download
./s3cmd.sh rm   people.parquet                   # delete
```

Override defaults via env: `MINIO_BUCKET`, `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY`,
`MINIO_SECRET_KEY`, `MINIO_NETWORK`. For minio2:
`MINIO_ENDPOINT=http://minio2:9000 MINIO_BUCKET=test-bucket-2 ./s3cmd.sh ls`.

## Fixtures

[`fixtures/`](fixtures/) is checked-in seed data, shared between the standalone
stack here and the integration-test single-MinIO service in
`compose.test.yml`:

| File | Rows | Used by |
|---|---|---|
| `people.{csv,ndjson,parquet}`, `age.ndjson` | 5 | small ad-hoc fixtures, kept for debug |
| `regions.parquet` | 200 (`region_id, campaign_id, region_name, country, population, ad_spend`) | python integration suite |
| `web_events.csv` | 5000 (`event_id, campaign_id, product_id, event_type, session_seconds, value`) | python integration suite |
| `campaigns.ndjson` | 50 (`campaign_id, campaign_name, budget, status`) | python integration suite |

The three integration-suite fixtures are regenerated by
[`fixtures/generate_external_fixtures.py`](fixtures/generate_external_fixtures.py)
(seeded → reproducible; needs `pyarrow` + `faker`):

```bash
python tests/minio/fixtures/generate_external_fixtures.py
```

After editing fixtures, re-run `docker compose ... up -d` so the `*-init`
containers re-seed; a `down -v` wipes the bucket volumes.

### Regenerating the small parquet fixture

`fixtures/people.parquet` is a tiny binary used by debug poking:

```bash
python3 -c "import pyarrow as pa, pyarrow.parquet as pq; \
pq.write_table(pa.table({'id': pa.array([1,2,3,4,5], pa.int32()), \
'name': ['Alice','Bob','Charlie','Dave','Eve']}), 'fixtures/people.parquet', compression='none')"
```

> Write it **uncompressed** (`compression='none'`) if you're targeting an Arrow
> build without the snappy codec. The integration build does enable snappy
> (see `conanfile.py`), but the smaller debug images may not.
